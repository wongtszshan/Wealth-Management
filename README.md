# 澄理 · Wealth Management

个人财富管理 PWA。以资产负债、财富变化、财务目标为主，日常收支为底层明细。当前版本 **v2.1.3**。

## 支持范围与现状
- **现金与存款**：中国、新加坡银行账户，可根据实际情况另选 USD；余额、昵称、地区、记录日期、流动性标签。原有独立账户入口已合并，历史交易账户标签保留。
- **现金管理类理财**：与银行现金分开记录，朝朝盈 2 号等产品按手动持仓估值计入资产，不臆造每日收益。\n- **投资持仓**：美国股票（USD）、新加坡股票（SGD）；股票数量、单位成本、手动估值、估值日期、未实现盈亏。ETF / 基金是可选类型，**没有预设用户持仓**。
- **负债**：信用卡、贷款、房贷等未偿金额与记录日期。
- **净资产**：现金 + 持仓市值 − 负债。每个币种分别核算；跨币种汇总以 **SGD** 为展示基准，CNY→SGD、USD→SGD 汇率必须由用户手动填写。缺少必要汇率时不提供伪精确总额。
- **配置分析**：现金与股票结构、最大单一持仓、负债/资产比例；可设置每月必要支出，估算已标记可动用现金的覆盖月数。不提供无依据的财务健康分数。
- **财务规划**：目标金额、已专门预留资金、预定日期；未来单项大额支出和收入。计划不改变实际资产余额。
- **财富报告**：当前月 SGD/CNY 已录入收支汇总、净资产快照、自查清单、历史趋势及 JSON 导出；支持保存多次快照并保留历史。
- **原有功能保留**：交易流水、单笔记账、CSV、多张图片和 PDF 银行账单 AI 识别（人工核对）、月度比较、分类预算、储蓄目标、原有账户昵称、JSON / CSV 导出。

## 数据模型和防重复计算
新版存储格式为 version 2。新增 cashAccounts、holdings、liabilities、fxRates、wealthSnapshots、financialGoals、futurePayments、monthChecks、monthlyEssentialsSGD。旧交易和账户字段保留。
- 账户余额、证券持仓、负债采用**手动时点快照**；**不会**再从不完整的消费流水对这些余额进行加减。
- 银行转券商、股票交易、信用卡还款不应被误计为额外消费；目前尚无完整复式记账和自动跨账户勾稽，请谨慎分类。
- 财富估值变化不等同于投资已实现收益；月度收支结余不等同于净资产变化。
- 汇率未联网更新，股票价格也**不**自动从行情服务获取。估值、日期、数据完整性需用户负责。
- 基金、房产、保险、自动股息/拆股、税费、成本批次、精确投资组合收益率和 AI 分析未做完整实现；本版是以现金、股票、负债为核心的管理基础版。

## 隐私与同步
前端 GitHub Pages：`https://wongtszshan.github.io/Wealth-Management/`。
云端 Worker：`https://wealth-management-api.wangtszshan.workers.dev`。
独立 GitHub 私库：`wongtszshan/Wealth-Management-data`，加密文件 `finance.cloud.encrypted.json`。
- 浏览器账本保存在本机 localStorage，**未加密**；请只在信任的设备使用。
- 登录后由 Cloudflare Worker 进行 AES-GCM 加密并写入私库；Worker Secret 管理 GitHub Token、登录口令和加密密钥。**不是端到端加密**。
- 已有旧账升级时保留旧字段；本地与云端发现差异会暂停自动覆盖。本机录入新版资产时也会参与冲突检测。
- 建议升级前用「设置与同步 → 导出本地 JSON 备份」独立备份。不要修改或遗失 DATA_ENCRYPTION_KEY。
- 163 / OCBC 邮箱**未接入自动读取或转发**，避免扩大私人邮箱访问权限。银行账单采取按需手动导入。
- 图片和 PDF：仅选定页面在点击识别时传至 Worker 和所选 AI 模型商；PDF 原文件不会写入私库。识别结果需要人工复核。

## 使用节奏建议
1. 首次建立银行现金账户、现有美股与新加坡股持仓、负债，以及必要参考汇率。
2. 不定期导入消费流水；月底更新账户余额、股票估值和负债。
3. 在「财富报告」中完成月度自查清单并保存快照。
4. 每季度检视资产配置、资金目标、集中度、现金覆盖和历史净资产变化。

**注意**：报告和健康指标属于个人财务整理，不构成投资建议，不代表对账已由银行确认。

## 账户统一与余额校对（v2.1.0）
- 旧的「原有账户」导航已合并到「资产与负债」。历史交易账户名称及记录保留；对招行/OCBC 账户采用相同稳定 ID 关联，交易录入选择账户来自统一资产账户列表（并兼容旧昵称）。
- 「校对余额」针对实际余额与已记录余额不同的情况，产生类别「其他」、类型「余额校对」的单独审核记录，含正负差额和备注「校对操作产生的差额」。该类型**不计入消费、收入或预算**，避免凭空产生费用。普通月度余额更新请选择「编辑」，不会自动生成校对记录。
- 2026-11-19 用户提供的三项余额被安排在 Cloudflare Worker 的**已登录读取私库**阶段一次性合并；执行前保留了私库加密备份 `backups/finance-before-account-unification-2026-11-19.encrypted.json`。由于无法读取原有加密密钥，服务器需由已有授权会话触发读取后才能完成加密私库写入；仅部署代码不代表已经完成迁移。完成后需验证私库文件 SHA 发生变化、账户金额正确。

## 兴业银行 → 观山海房贷核对（v2.1.0）
- 在「资产与负债」编辑负债 **观山海** 时，可以关联实际扣款的 **兴业银行** 现金账户（不修改现有负债数额）。
- 导入兴业银行 CSV、PDF、图片后，在待确认交易区可以为同币种流水批量指定账户。已导入并匹配的后续扣款会在确认导入时提示核对。
- 「观山海」卡片的「关联兴业扣款 / 核对还款」选择一条未关联、日期严格晚于当前贷款余额日期的真实扣款流水，填写已由贷款明细核实的**本金**与**利息及费用**。两项合计必须等于扣款金额；本金不得超过未偿余额。
- 确认后仅**本金**减少「观山海」负债，利息及费用计入「住房账单」支出；银行现金余额维持用户原先的手动余额快照，**不再次扣除**，避免账面重复扣减。保存关联编号、原始银行交易、扣款前后未偿余额，阻止一笔扣款重复关联及直接删除；可在没有后续余额变动时安全撤销。
- **重要限制**：只有银行扣款总额、没有贷款还款计划的本金/利息拆分时不能自动推定本金，故导入后先产生「待核对」候选，须经用户确认后才会更新负债。系统当前未接通兴业贷款本息明细自动接口；旧于当前负债快照的历史还款不能再次抵扣。
- 历史导入的交易仍可能缺少银行账户标记；请在待确认区选择兴业账号，之后在负债中人工选择对应扣款，避免误配招行转入、账户内部划转或非房贷消费。真正的招行→兴业内部转账跨行自动匹配仍属于下一阶段。

## v2.1.0：moomoo 券商账户 → 现金 / 持仓 → 交易
- 新增 `brokerageAccounts`（券商账户），原持仓 `holdings` 继续保留、不修改当前 MRVL / 093 的持仓数值。没有显式券商归属的旧持仓会在界面上归入默认 moomoo 名下；**查看页面不会自动在私库写入新的账户记录**。
- 券商账户可录入 SGD / USD / CNY 现金余额、券商报告净值、报表币种及日期。账户内部计算价值 = 各币种现金 + 关联股票市值（需参考汇率）。**若录入券商账户净值，财富总览以账户净值为这一券商的资产整体计入一次，内部股票/现金仅作拆解与对账，绝不重复累加；若没有录入账户净值，则暂按已知明细估算，可能不完整。**
- 未填写券商现金数据时显示「未录入」，对账差额不以 0 代替；未完成必要汇率转换时不伪造统一口径。
- `investmentTrades` 保存买入、卖出、现金分红；以当前旧持仓作为**期初持仓快照**，后续记录按移动加权平均成本计算剩余持仓、已实现盈亏、未实现盈亏及分红；手续费进入买入成本或从卖出款中扣除。记录无法使持仓为负，且可撤销无后续错误的记录。
- 市价更新独立于成交记录。已有交易的期初数量和成本不能任意编辑，避免历史数据不一致。
- **限制**：目前买卖流水不会自动改变券商账户手工填写的现金余额，不能当作完整的自动现金对账；操作后的最新现金数应按 moomoo 报表核实更新。当前也未处理融资/保证金负债、拆股、公司行动、代扣税、汇兑成本、跨币种回报等；券商总资产与独立计算的差额需要进一步核对。不从截图猜测精确现金数据。
- 现有资产/负债、银行收支、加密同步和备份字段保留。新数组在旧账迁移时默认空白。

## v2.1.3 · moomoo 股票成交截图导入
- 股票持仓页面增加专用的 PNG / JPG / WEBP 多图片上传，最多 5 张、单张最多 4MB；只在用户点击「开始识别」后，经已有登录会话发送给 Cloudflare Worker，再交由所选 Kimi/Claude API 处理。原图不写入私库。
- 识别模型与银行流水使用不同提示词：仅提取实际全部成交/部分成交的证券执行记录。**已撤单、未成交、成交数量为零**的订单不入账；以 **已成交均价** 而非委托价格记账。
- 识别日期不见时保留空白，手续费未知时也保留空白，用户必须补齐或明确填写零。所有候选在网页可逐笔选择/编辑：证券关联、成交日期、数量、成交均价、手续费。
- 校验交易先于原有期初持仓日期、重复委托号或同日同证券同方向同数量同均价、卖出超过可用数量、错误币种；**任何一笔失败则本批次不提交**。自动识别 O39 / 093 等不一致股票代码时不会静默关联，需要人工确认。
- 最终确认时才追加 `investmentTrades`，保留来源图片文件名和委托号（如可见），并计算移动平均成本、持仓数量与盈亏；不直接覆盖现金、账户净值、既有持仓或银行流水。
- **限制**：示例委托截图无完整成交日期和手续费，不能据此直接改变资产。若要从最早历史成交重建完整投资持仓，须另外建立起始持仓对账/全量重建流程，不能直接叠加到已经包含这些成交的期初持仓。
